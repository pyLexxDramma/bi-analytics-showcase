## Главное ограничение

**Десктоп (`lg+`, ≥1024px) не меняется.** Любая правка этого цикла обязана быть
изолирована одним из двух способов:

- CSS — только внутри `@media (max-width: 1023px)`;
- TS/TSX — только под runtime-проверкой (`useIsMobileViewport()` / ветка `compact`).

Правки, меняющие desktop-рендер, в этот цикл не входят. Паритет `lg+` с main,
принятый в §0–§16, остаётся эталоном и не пересматривается.

## M1. Тач-физика и скролл 🔄

**Проблема.** `PLOTLY_CONFIG.scrollZoom = true` действует и на телефоне, `dragmode`
по умолчанию `zoom`: палец внутри графика рисует рамку зума, страница не листается.
Горизонтальные обёртки графиков без `touch-action` / `overscroll-behavior` —
вертикальный свайп «залипает».

**Правки:**

- `web/src/lib/use-is-mobile.ts` — общий хук `useIsMobileViewport()` (matchMedia 1023px).
- `web/src/components/plotly-figure.tsx` — на мобиле `dragmode: false`, `scrollZoom: false`
  (кроме развёрнутого режима); desktop-конфиг не трогаем.
- `web/src/components/fullscreen-panel.tsx` — на мобиле вместо native Fullscreen API
  (не работает для `div` в iOS Safari) fixed-оверлей; внутри график снова интерактивный.
- `web/src/app/globals.css` — только `@media (max-width: 1023px)`: `touch-action: pan-y`
  на полотне Plotly, `pan-x` + `overscroll-behavior-x: contain` на горизонтальных
  скроллерах, scroll-snap по категориям, градиентные фейды по краям.

**Проверить на телефоне:**

1. Свайп пальцем поверх любого графика листает страницу.
2. Горизонтальная прокрутка широкого графика не тянет страницу и не «отскакивает».
3. Видно, что график продолжается за краем экрана.
4. «Развернуть» открывает график во весь экран, там зум и панорама работают.
5. Desktop (`lg+`) — без изменений: modebar, зум, ⛶ как раньше.

  демо ставится иконкой на домашний экран.
- ✅ Все мобильные анимации (лист, backdrop, скелетон, нажатие триггера)
